# 公司形象網站 UI UX 與動態設計

## 1. 背景與問題

依 [已核准 SPEC](../spec/20261019-0001-company-website.md)，將練習專案轉為三頁雙語形象網站。使用者於 2026-10-19 授權「確認 SPEC，進入 DESIGN」；本文件是 L2 詳細設計草稿，尚未核准實作，不自行進入編碼或清理舊程式。

## 2. 目標

建立具有辨識度的 UI／UX 與動態語言，讓訪客依序理解品牌、業務、公司背景。動畫承擔資訊引導與狀態回饋，不以特效數量代替品質。主要行為及非範圍引用 SPEC §2～§3。

## 3. 範圍與非目標

包含視覺、資訊層級、互動狀態、雙語路由、元件責任與驗收策略。不選購服務、不建後端、不新增 SPEC 外功能。不提供 /practice，也不將舊練習翻譯或搬到另一入口。

## 5. 方案比較

| 方案 | 優點與限制 | 取捨 |
|------|------------|------|
| 通用卡片加淡入 | 簡單，但不足以回應獨特動畫要求 | 不採為主體 |
| 全螢幕 WebGL／捲動接管 | 視覺強烈，但提高載入、手機與鍵盤風險 | 不採 |
| 幾何構圖與內容互動整合 | 可用輕量 SVG、CSS、局部狀態表現，與品牌識別一致 | 建議採用 |

先以 CSS transitions／keyframes、原生 SVG 與必要的局部 React 狀態實現，不預先新增動畫套件；SVG 為程式圖形，不需生成點陣圖片。若無法達成確認後的風格，先回報差異再調整工具。

## 6. 已核准設計

### 6.1 視覺概念：由線成形

將「澄」的清晰與「岳」的層次轉化為細線、斜面及幾何框景。首頁以分離的輪廓線組合成抽象山形／字標構圖；業務頁沿用同一構圖變形；公司頁以同源線條串接經歷。避免三頁各自使用無關特效。

| 設計元素 | 提案 |
|----------|------|
| 色彩 | 深藍 #11283F、暖白 #F6F3EC、青綠 #087F78；次要文字 #526170。以語意變數定義，實作檢查對比後微調，不以色彩單獨表達狀態。 |
| 字體 | 系統中文字體與無襯線英文；大標題有編輯式換行，小型頁面編號協助層級。不依賴外部字體下載。 |
| 排版 | 桌面留白與非對稱雙欄、線條分隔及大字標題；手機單欄，先文字後構圖。避免每段都裝入相同圓角卡片。 |
| 共用介面 | 頂部字標、三頁導覽、中英切換；目前頁面以文字及線條雙重標示。頁尾保留示範標示，不放無作用的聯絡按鈕。 |

### 6.2 三頁構成與動態分鏡

| 頁面 | 主要畫面與互動 | 動態分鏡 |
|------|----------------|----------|
| 首頁 F01 | 上方字標導覽；左側大標與兩個導覽入口，右側抽象線條構圖；下接三項業務摘要與公司簡介 | 輪廓線 700～900ms 匯聚成形，文字逐組 60ms 錯開、400～500ms 到位；向下閱讀時以線條延伸串接區塊。正文不等待動畫才出現或可操作。 |
| 公司介紹 F02 | 左側編號業務列表，右側大面積說明與幾何圖形；手機列表在內容上方 | 選取業務時線條與斜面在 250～400ms 變換構圖，說明作輕微位移及透明度轉換，選取指示同步移動；切換品牌／網站／介面各有同源但不同輪廓。 |
| 關於公司 F03 | 公司簡介與地址標示，接縱向三階段經歷 | 沿軸線隨閱讀呈現節點；展開經歷時連接線與區塊同步展開 200～300ms，指示符旋轉；節點標題始終可見。 |

本表為視覺及分鏡提案，不是已完成預覽。核准前需使用者確認「線條匯聚、非對稱排版、同源幾何變形」方向；若需更具體畫面可在本階段補靜態線框或動態參考，不將文字提案冒稱視覺驗收完成。

### 6.3 互動契約與例外

- 業務採 tabs：第一項預設啟用，方向鍵循環移動並啟用，Home／End 到首末項；Tab 進入啟用項後可離開至內容。以 aria-selected、tab／tabpanel 關係及可見焦點標示。快速連續切換直接以最新項目為準，取消過時動畫，不排隊鎖住操作。
- 經歷採獨立展開按鈕：Enter／Space 切換，aria-expanded 與面板關聯；預設全收合，多項可同時開啟，焦點留在觸發按鈕。收合中的隱藏內容不進入 Tab 順序。
- 行動導覽採非模態展開區：開啟後順序可達連結；Escape 收合並回到觸發按鈕，點選連結後關閉。切至桌面解除隱藏與過期開啟狀態，不留下焦點陷阱。
- 各頁區塊進場每次掛載僅一次，不因來回捲動反覆播放；不接管捲動，不使用強制游標追蹤或需要滑鼠才能取得的資訊。觸控以點選完成同等操作。
- prefers-reduced-motion 下取消線條描繪、位移及錯開，保留即時內容更新和狀態標示。動畫失效時內容仍可讀；不以 opacity:0 當成內容永久初態。
- 英文文字較長時允許換行，面板不固定文字高度，動畫結束後內容不裁切；不以縮小字體掩蓋溢出。

### 6.4 路由、翻譯與邊界

目標檔案僅為實作規劃，尚未建立：

```text
src/app/[locale]/layout.tsx
src/app/[locale]/page.tsx
src/app/[locale]/services/page.tsx
src/app/[locale]/about/page.tsx
src/app/not-found.tsx
src/i18n/{routing,navigation,request}.ts
src/app/page.tsx（靜態入口導引）
messages/{zh-TW,en}.json
src/components/site/（導覽、頁尾、主視覺、業務與經歷互動）
```

locale layout 驗證 zh-TW／en，提供語系語意與對應 metadata；根入口與各語系的 document lang 配置須一併驗證。依選定 next-intl 版本配置可靜態執行的 request、provider 及 Next plugin。靜態內容與頁面組合優先 Server Component；只在導覽開關、語言切換、業務選取、經歷展開與必要進場觀察建立 Client boundary。

靜態部署不使用 proxy。根 layout 提供外層 html／body，語系頁面明確提供對應語言屬性與 metadata；實作前確認可同時產出根入口、兩語頁與 404 的 layout 結構，避免重複 html。以 generateStaticParams 預先列出 zh-TW、en，使用選定版本可靜態渲染的 next-intl request 設定，不讀執行期 cookies 或 headers。

站點入口固定以瀏覽器導向 /zh-TW/（加部署基底），入口靜態 HTML 同時提供中文、英文直接連結；JavaScript 關閉也能進入內容。六頁均以目錄式 index.html 匯出，未知路徑由 GitHub Pages 404.html 處理，不用 SPA rewrite 假裝所有路徑成功。404 含中英文說明及帶正確基底的回首頁連結，不載入任意語系訊息檔。

### 6.4.1 GitHub Pages 靜態交付

【官方】2026-10-20 查閱 [Next.js 靜態匯出](https://nextjs.org/docs/app/guides/static-exports)、[next-intl 靜態部署限制](https://next-intl.dev/docs/routing/middleware)、[GitHub Pages 說明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。靜態匯出不支援 Proxy、執行期伺服器 redirects 等功能；此處方案尚未實作驗證。

- next.config 採 output: export、trailingSlash: true，產物 out/；不使用 next start 作為此交付的正式執行方式。
- 預設以專案 Pages 規劃 basePath=/實際儲存庫名稱；若為帳號專屬站則空基底。部署前依真實 repository 查證，不猜帳號。頁面、語言切換、圖形、圖片、favicon、CSS／JS 與 404 連結均須適用基底，不另以 assetPrefix 替代完整路徑處理。
- 圖片採本機靜態資源或 inline SVG；如採 next/image 則關閉需伺服器的預設最佳化，不新增外部付費圖片服務。
- 規劃 GitHub Actions：固定 pnpm／Node 版本、frozen-lockfile 安裝、品質檢查、建置、上傳 out artifact、以 Pages 官方部署機制發布；部署 job 只需 contents:read、pages:write、id-token:write 與 github-pages environment，固定併發避免互相覆蓋。執行分支依 repository 設定查證，不預設分支名稱。
- out/、安裝產物與大量可重現輸出不提交；工作流程與 .nojekyll 靜態設定依實際發布機制核對。GitHub Pages 可用性、權限與公開網址於部署時確認，不預先宣稱免費方案或私有儲存庫皆可使用。
- 公開交付以 Pages HTTPS 網址為準；不以 file:// 開啟產物，也不以僅完成本機靜態伺服器驗證宣稱線上完成。

語言切換透過 locale-aware navigation 到對應 pathname；操作中防重複啟動，失敗時保留原頁與可重試入口，不顯示假成功。切換後業務及經歷回預設狀態，行動選單關閉。翻譯 namespace 按 Common／Home／Services／About／Metadata；結構與非空 key 兩語比對，缺漏屬交付失敗，不默默以另一語言混補。

### 8.2 手機、翻譯及動態補充

- 768px 以下以單一主構圖為焦點，不同時播放多組裝飾；保留品牌線條成形語言，縮短位移與取消跨欄轉場。業務內容切換、經歷展開仍有可辨識回饋；不隱藏核心內容。
- 內容進場最多每組 3 個錯開元素，避免長段文字逐字動畫；離開畫面的裝飾不持續計算。減少動態偏好變更後立即套用，不需重新整理。
- 中文與英文共用資訊結構與圖形容器，文字區高度依內容伸展；驗證英文較長標題、導覽與業務說明，不將英文版留到最後翻譯。F02 一律以業務服務／Services 對外呈現，先前分鏡中的「公司介紹」為歷史稱呼。
- 語言切換與內容導覽皆用真實連結／控制元件；小圖示需可理解名稱、點選區域原則至少 44×44 CSS px，焦點可見；動畫不能替代文字標籤。
- 當手機直橫切換或容器尺寸改變時重新適配幾何構圖，不重播所有進場動畫或重設訪客已展開的內容。英文切換可依 SPEC 重設互動狀態。

### 8.3 部署失敗與恢復

最小部署及正式部署都只發布通過建置檢查的 artifact；錯誤不以 SPA fallback 或硬編碼本機網址掩蓋。建置／部署失敗不標為 completed，保留上一個可用線上版本；如新版本有問題，以已知可用版本重新部署恢復，不以強制推送或重寫歷史處理。實際回復工作流程在部署前依 repository 設定確認，不宣稱已具備自動回復。

公開前確認示範標示、中英內容、資源授權及不含私密資料；不把來源碼已推送或 Actions 建置成功等同 Pages 網址可用。未獲 Commit／Push 授權不進行相應 Git 操作。
