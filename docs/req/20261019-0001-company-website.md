來源記載的原始方向為建立公司形象網站，提供首頁、公司介紹、關於公司三個頁面，不需要管理後台。來源中的環境、套件與儲存庫現況屬歷史快照，本次未重新驗證，不作為功能已完成的證據。

## 2. 目標

- 建立公司對外形象網站入口。
- 以三個頁面呈現公司資訊，明確區分「公司介紹」與「關於公司」的內容責任。
- 提供足夠的互動體驗與動畫，作為使用者於本次對話明確提出的驗收方向；不能只以三頁靜態內容存在判定完成。
- 動畫呈現風格與 UI／UX 設計為核心品質要求：須具有品牌辨識與特別的視覺表現，並融入資訊層級、導覽及內容互動；不能僅套用通用淡入效果就視為滿足。
- 在 SPEC／DESIGN 中釐清品牌素材、內容與網站範圍；可先整理不依賴未決事項的草稿，依賴未決內容的實作須等待相應確認。本次僅處理文件。

## 3. 需求範圍與非範圍

本需求涵蓋首頁、業務服務、關於公司三頁及中英文多語系；不建立管理後台。F02 原稱「公司介紹」，依 2026-10-20 使用者同意改善建議，對外名稱改為「業務服務／Services」；功能鍵、責任及原始基準不變。前述來源紀錄與歷史提案中的舊稱均指同一功能。

目前不納入：會員、購物車、資料庫、CMS、管理介面、聯絡表單寄信及流量追蹤。多語系已依使用者後續要求納入，提供繁體中文與英文，並指定使用 `next-intl`；這是需求與技術限制，不表示套件已安裝或功能已實現。

使用者於 2026-10-20 確認採靜態展示並放在 GitHub，供訪客不啟動本機伺服器即可瀏覽；部署採 GitHub Pages 與 Next.js 靜態匯出。pnpm 轉換方案亦已確認。Markdown／MDX、額外動畫套件與編輯器插件未因本次確認而自動採用。

三頁指首頁及兩個獨立內容頁；以單頁三區塊替代須另確認需求變更。使用者於 2026-10-19 明確說明：「公司介紹」介紹業務性質；「關於公司」介紹公司本身，包含地址、經歷等內容。各頁網址、實際文案與導覽方式仍待釐清。空白頁、佔位內容或相同內容重複三份不能作為三項功能完成的證據。

「關於公司」包含地址；地址實際內容與呈現方式，以及地址以外的聯絡資訊是否納入，仍待確認，不隱含地圖服務、聯絡表單、寄信或資料蒐集。「內容更新」也不隱含 CMS、後台或資料庫，方式仍待確認。除外項目若要加入，須先記錄並確認範圍變更。
